# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Repository overview

This is a Shopify theme for the **elementsofdecor** store, based on **Shopify Dawn v15.4.1** (see `config/settings_schema.json` → `theme_info`). It is a pure Liquid/JS/CSS theme — there is no `package.json`, build pipeline, or test runner. All work happens against Shopify's CLI / Theme Editor.

## Common commands

Development relies on the Shopify CLI (`shopify theme ...`). There are no npm scripts.

- `shopify theme dev` — local hot-reload dev server proxied to the store
- `shopify theme pull` — pull live theme settings/templates from the store (the JSON files in `templates/` and `config/settings_data.json` are auto-generated by the Theme Editor; expect them to drift)
- `shopify theme push` — upload to a development/unpublished theme (never push to live without an explicit ask)
- `shopify theme check` — lint Liquid (no `.theme-check.yml` is committed, so it uses defaults)

There is no test suite. Verify changes by running `shopify theme dev` and exercising the affected templates in a browser.

## Architecture

Standard Shopify theme layout — the directories are not arbitrary, they are contracts with the Shopify platform:

- `layout/theme.liquid` — root HTML wrapper rendered for every page; `password.liquid` is the password-page wrapper. All `<head>`, global stylesheet/script tags, and `{{ content_for_layout }}` live here.
- `templates/*.json` — page-type templates (product, collection, index, etc.) as JSON section trees. **These files are auto-generated by the Theme Editor** (note the header comment in each). Hand-editing is possible but the Theme Editor will overwrite. Customer-account templates live in `templates/customers/`.
- `sections/` — 54 Liquid sections, each with a `{% schema %}` block defining settings exposed in the Theme Editor. `header-group.json` and `footer-group.json` are section groups.
- `blocks/` — app/theme blocks usable inside sections. Currently contains one AI-generated editorial block (`ai_gen_block_8cddce1.liquid`); preserve the `{% doc %}` prompt header when editing.
- `snippets/` — 37 reusable Liquid partials rendered via `{% render 'name' %}` (Dawn convention: prefer `render` over `include`, pass variables explicitly). Card components (`card-product`, `card-collection`, `article-card`), header variants (`header-mega-menu`, `header-drawer`, `header-dropdown-menu`), and product-media helpers live here.
- `assets/` — 185 files: per-component CSS (`component-*.css`, `section-*.css`), per-component JS modules (`cart-drawer.js`, `product-form.js`, `global.js`, etc.), and SVG icons. CSS files are referenced from sections/snippets via `{{ 'foo.css' | asset_url | stylesheet_tag }}`; many use `preload_tag` or `defer`. There is no bundler — every file is shipped as-is.
- `config/settings_schema.json` — defines theme-wide settings UI; `settings_data.json` is the merchant's saved values (auto-generated, expect churn from Theme Editor).
- `locales/` — 51 translation bundles. `en.default.json` (storefront) and `en.default.schema.json` (Theme Editor labels) are the source of truth; other locales mirror their keys. Liquid references them via `{{ 'key.path' | t }}`.

## Working agreements

These are explicit user instructions for how to work in this repo.

- **Docs first, code second.** Before searching the codebase for how something works, check `README.md`, this `CLAUDE.md`, and any `docs/` content. Only fall through to grep/Read when the docs don't answer the question.
- **Document while you work.** When implementing a new section, snippet, block, or non-trivial behavior change, capture it in the docs as part of the same change — what was added, why, and which sections/snippets/assets it touches. Don't leave doc updates for "later".
- **Update docs after changes.** Once a change lands, update `README.md` / `CLAUDE.md` (and any feature-level docs) so they reflect the new state. Stale docs are worse than no docs.
- **Test-driven where possible.** Write the test or a verification harness first, then the implementation. Shopify themes have limited automated test surface, so in practice this means: for JS in `assets/`, add a test (or at minimum a runnable verification snippet) before changing logic; for Liquid changes, write down the storefront states you'll exercise in `shopify theme dev` *before* editing, and verify each one after.
- **Shopify best practices.** Prefer Dawn-native patterns over custom ones (`{% render %}` over `{% include %}`, section settings over hardcoded values, the `t` filter for all storefront copy, `image_url` with explicit `width`/`height` over raw `img_url`, `asset_url | stylesheet_tag` / `script_tag` over inline). Respect the section/block schema contract — don't introduce settings that aren't editable in the Theme Editor when an editable equivalent exists.
- **Make things merchant-configurable by default.** Whenever you add or change behavior, expose the knobs to the merchant rather than hardcoding values. In order of preference: section/block `{% schema %}` settings (per-instance, edited in the Theme Editor) → theme settings in `config/settings_schema.json` (global) → metafields (per-resource: product/collection/customer/page) → metaobjects (structured, reusable content). Hardcode only when none of these fit, and call that out in the change description.
- **Ask before assuming.** When the task is ambiguous — unclear scope, unstated copy/colors/breakpoints, unclear which template/section is in play, unknown metafield/metaobject definitions, or a choice between "configurable vs. hardcoded" that affects the schema — stop and ask. A single clarifying question up front beats a wrong implementation that has to be redone.
- **Performance is a first-class requirement.** Treat every change as a potential regression to LCP/CLS/TBT. Concretely: lazy-load below-the-fold images (`loading="lazy"`, explicit `width`/`height`), preload only above-the-fold critical assets, defer non-critical JS (`defer`/`type="module"`), avoid adding new render-blocking CSS files when an existing component CSS can be extended, prefer CSS over JS for animation, and avoid duplicate asset includes across sections. When adding JS, scope it to the section/snippet that needs it rather than `theme.liquid`.

### Things to know when editing

- **Auto-generated files**: `templates/*.json` and `config/settings_data.json` carry an "auto-generated" warning header. Treat them as state owned by the Theme Editor — small structural edits are fine, but expect `shopify theme pull` to overwrite cosmetic changes.
- **Adding a setting** to a section means editing both the `{% schema %}` block in `sections/<name>.liquid` and (if user-facing strings) `locales/en.default.schema.json`.
- **Adding storefront copy** means adding the key to `locales/en.default.json` and referencing it via the `t` filter — never hardcode user-visible strings.
- **CSS/JS additions**: add the file under `assets/` and reference it from the section/snippet that needs it. There is no global bundle to update.
- **Dawn upstream**: this theme tracks Dawn 15.4.1. Before adding cross-cutting changes, check whether Dawn already has a snippet/section for it (especially `card-*`, `header-*`, `product-*`, cart-drawer pieces) rather than introducing a parallel implementation.
